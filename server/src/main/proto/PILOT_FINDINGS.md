# Step one: protobuf for inter-node communication

This change is the first step in moving OpenSearch's inter-node protocol from hand-written
`StreamInput`/`StreamOutput` serialization to protobuf. It establishes the mechanism on one API
(`_cluster/health`) with no user-visible change, so that every later message migration is a repeat of the same
small recipe.

## The mechanism

Every transport message is **header fields** (task, routing and timeout metadata owned by the base classes)
followed by a **payload** (the action-specific fields). The root classes now say so and decide how the payload is
encoded:

```java
// TransportRequest (TransportResponse has the same, without header fields)
public void writeTo(StreamOutput out) {
    writeHeaderFields(out);
    if (this instanceof ProtobufPayload) ProtobufPayload.writePayload((ProtobufPayload) this, out, this::writeLegacy);
    else writeLegacy(out);
}
```

`ProtobufPayload` (`libs/core`, bytes only, no protobuf dependency) is the opt-in: `protobufSince()` and
`protobufBytes()`. Peers at or after `protobufSince()` get the serialized message; older peers get the frozen
pre-protobuf layout from `writeLegacy`. The leaf constructor mirrors this with `ProtobufPayload.readPayload`.

Nothing else moves. Action names, `ActionType`s, request/response class names and public methods, the REST
handler, `ActionModule`, plugin extension points (`ActionFilter`, `IndicesRequest.Replaceable`) and the transport
layer are unchanged. Legacy leaves still override `writeTo` and call `super.writeTo(out)`; same bytes, same order.

## Migrating a message (the recipe)

1. Write the `.proto` next to the Java package (`server/src/main/proto/org/opensearch/...`).
2. Make the class `implement ProtobufPayload`; store the generated message as its only state; accessors read it
   and own defaults, sentinels and conversion to domain types; setters rebuild it. `message()` and the
   message-wrapping constructor are package-private.
3. Rename the old `writeTo` body to `writeLegacy` and the old `StreamInput` constructor body to a static
   `readLegacy`. These are frozen and die with the compatibility window.
4. Add `PROTO_SINCE`, `protobufSince()`, `protobufBytes()`.
5. Leave the transport action alone. It reads the request through the same public accessors as before, so its
   class, constructor, registration and logic do not change.
6. Pin the legacy layout with golden bytes generated by the previous release's artifact.

Adding a field afterwards is one line in the `.proto`. `writeLegacy` is never touched again.

## Decisions

- **Enums `_UNSPECIFIED = 0`, every scalar `optional`, sentinels modelled explicitly** (`ActiveShardCount` as
  `oneof count|sentinel`). "Absent" is distinguishable from the default.
- **Header fields stay in the legacy stream on both encodings.** This is what keeps routing, retry, task
  registration and filters untouched. Moving them into a proto header later is a change to `writeHeaderFields`
  alone.
- **Logic reads the request and response classes, not the generated messages.** An earlier revision of this
  pilot ported `TransportClusterHealthAction` onto `ClusterHealthRequestProto.ClusterHealthRequest`. The logic
  ended up reading fields three ways (raw getters, `ProtoConverters.fromProto`, and static helpers that applied
  defaults), passing `local` separately because header fields are not in the message, and losing the shortened
  timeout on a `NotClusterManagerException` retry because the immutable message could not carry it. The accessors
  that apply defaults have to stay for the public API anyway, so the action now uses them and is identical to
  `main`.
- **Rich domain types** (`ClusterStateHealth` etc.) still compute health from `ClusterState` and own their own
  `writeTo`; the response projects them to proto. They are candidates for the same treatment later.
- **Deliberate behaviour changes:** `new ClusterHealthRequest().indices()` returns `[]` not `null` (the `null`
  NPE'd in `validate()`); `ClusterHealthResponse.equals` compares the whole message; request `toString()` prints
  the message.

## Hazards found

- `writeThin` in `ReplicationRequest` and `InstanceShardOperationRequest` called `super.writeTo` to mean "parent
  fields only" and now needs `super.writeHeaderFields`. Caught by the unit sweep; no other such caller exists.
- Generated class names shadow the Java classes (`ClusterHealthRequestProto.ClusterHealthRequest` vs
  `ClusterHealthRequest`). Pick a naming convention before the second migration.
- Code that mutates a request mid-flight relies on the setter replacing the message. The `wait_for_events` loop
  shortens `request.timeout(...)` so that a retry after `NotClusterManagerException` keeps the original deadline;
  porting that loop onto the immutable message silently dropped this.

## Next

1. `buf breaking` in `precommit`. Without it a field-number reuse is as silent as a bad version guard was.
2. A precommit ratchet: new classes in action packages that hand-write `writeTo` fail unless baselined, with the
   error linking the recipe. Plus the rule in `AGENTS.md`.
3. Golden-bytes generation as a build helper against the bwc artifact.
4. Second migration on a write-path action and on a `HandledTransportAction`.
5. Header fields into a proto header; then the payload is pure protobuf and the transport framing can change
   without touching any message.

Four earlier designs were tried and rejected on the way here: a second action name (not transparent to security
policies), a legacy action delegating to a proto action (still a second name), a proto-typed action facade (one
facade per action pattern), and parallel `Proto*` base classes (one per request family). Each was simpler than the
last; the root-level split is the smallest.
